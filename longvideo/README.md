# 長尺動画スタジオ（LongCat-Video × クラウドGPU）

画像1枚から、AIが短い動画（約5秒）を「前の続き」として何本も作り、つなげて長い動画にする自分専用システムです。
クレジット制のサービスは使わず、**RunPod で借りたGPUの時間料金だけ**で動きます。

> このフォルダは第1段階（画像1枚 → 動画）の実装です。ただし作りは最初から長尺用になっていて、
> 「続きの自動生成」「途中から再開」「失敗したところだけ作り直し」「連結して MP4 出力」まで入っています。

```
ふつうのPCのブラウザ ──HTTPS──▶ RunPod の GPU サーバー（/workspace）
  画像アップロード               ├ app.py（Streamlit 画面, ポート 8501）… ジョブ作成・進捗・プレビュー
  進捗・プレビュー               ├ lvgen.worker（常駐）……………… LongCat-Video で生成
  完成MP4のダウンロード ◀─────  └ jobs/<ID>/ …… セグメントごとに保存（落ちても続きから）
```

---

## 1. 調査結果：LongCat-Video は今回の用途に合うか（2026年11月14日時点）

公式リポジトリ（最終更新 2026-05-27, コミット `6b3f4b8`）のコードと README を読んで確認しました。

| 確認項目 | 結果 |
|---|---|
| ライセンス | **重みもコードも MIT**（README と LICENSE で確認）。商標・特許の権利は含まない。依存の Wan VAE / UMT5 は Apache-2.0 系 |
| 画像 → 動画 | ◯ `generate_i2v`。1回で 93 フレーム（480p / 15fps ≒ 6.2 秒） |
| 続きの生成 | ◯ `generate_vc`。前の動画の**末尾13フレーム**を引き継いで 80 フレーム（≒5.3 秒）追加。この作業で事前学習されているのが最大の強み |
| 長尺 | 公式デモは 11 回つなげて約1分。「数分の動画で色ずれ・劣化なし」と主張。**10〜20分の実績は公式には無い** → 第4段階で要検証 |
| 画質 | 生成は 480p/15fps。内蔵の refine LoRA で **720p/30fps** に上げられる。**1080p はモデル単体では出ない**（外部アップスケーラーが必要） |
| 速度 | 蒸留 LoRA で 50 → 16 ステップに短縮可能（本システムの「高速」モード） |
| 規模 | 13.6B パラメータ（密）。重みだけで DiT 約27GB + テキストエンコーダ UMT5-XXL 約11GB（bf16 換算の概算） |
| 音声 | なし（第5段階で別途） |

**結論：メインモデルとして妥当。** 「続きを作る」機能がモデル自体に入っているオープンモデルは少なく、MIT で自由に使えるのも大きい。
一方で、(1) 10分以上での人物・衣装の一貫性は未知数、(2) 1080p には別途アップスケーラーが必要、の2点は第2・第5段階の課題として残ります。

## 2. GPU の比較と、おすすめ構成

### 必要な VRAM（概算）

- 重みを全部GPUに載せると **約39GB + 計算用メモリ**。
- **80GB（H100 / A100）** … 余裕あり。まずここで動作確認。
- **48GB（L40S / RTX 6000 Ada）** … テキストエンコーダをCPUに逃がせば載る見込み（`start.sh` が自動で設定）。要実測。
- **32GB（RTX 5090）/ 24GB（RTX 4090）** … 重みすら載らないため、大幅なオフロードや量子化が必要で非常に遅くなる。
  さらに 5090 は Blackwell 世代で、公式の PyTorch 2.6 / flash-attn 2.7.4 が対応していない。**このモデルの本番運用には不向き**。

### 料金（RunPod, 第三者サイトの2026年9〜10月時点の値。公式ページは必ず再確認）

| GPU | VRAM | 時間単価の目安 | 第1段階で使えるか |
|---|---:|---:|---|
| H100 PCIe / SXM | 80GB | $2.89 / $3.49 | ◎ 最速 |
| A100 80GB | 80GB | $1.59〜1.79 | ◎ 速度は H100 の半分前後と見込む |
| L40S | 48GB | $0.79〜1.09 | ◯ オフロード前提。要実測 |
| RTX 5090 | 32GB | $0.69〜0.99 | ✕（未対応・VRAM不足） |
| RTX 4090 | 24GB | $0.74〜0.89 | ✕（VRAM不足） |

※ この作業環境からは runpod.io に接続できなかったため、公式料金ページは直接確認できていません。

### 10分動画のコスト見積り（考え方）

10分 = **113 セグメント**（6.2秒 + 5.33秒 × 112）。合計時間は「1セグメントの時間 × 113」で決まります。

| H100 での1セグメントの時間（仮定） | 10分動画の合計GPU時間 | 料金（H100 SXM $3.49/時） |
|---:|---:|---:|
| 1 分 | 約1.9 時間 | 約 $6.6 |
| 2 分 | 約3.8 時間 | 約 $13 |
| 4 分 | 約7.5 時間 | 約 $26 |

A100 や L40S は時間単価が半分〜3分の1ですが、そのぶん遅くなる見込みなので、**1本あたりの料金は H100 と大きくは変わらず、完成までの時間が延びる**と予想しています。

**1セグメントあたりの実際の時間はまだ測っていません。** 第1段階の動作確認（下の手順 6）で実測し、画面にも「生成○秒・VRAMピーク○GB」が記録されます。
この数字が出れば、GPUごとの「1本あたりの料金」を正確に比べられます。

### おすすめの進め方

1. **H100 80GB で動作確認**（失敗要因を減らすため）。短い動画を数本作り、1セグメントの時間と VRAM ピークを記録。
2. 同じ画像・設定で **A100 80GB** と **L40S 48GB** を試し、「1本あたりの料金」を比較。
   計算性能あたりの料金はどれも近いので、**料金差は小さく、待ち時間（速さ）で選ぶ**ことになる可能性が高いです。
3. 待機中も課金されるので、**使わないときは Pod を停止**（データは /workspace に残る）。

## 3. 導入手順（初心者向け・一つずつ）

### 手順 1：RunPod のアカウントを作る

1. https://www.runpod.io/ でサインアップ。
2. 「Billing」でクレジットをチャージ（最初は $25 程度で十分）。

### 手順 2：ストレージ（ネットワークボリューム）を作る

モデルの重み（数十GB）と作った動画を保存する場所です。Pod を消しても残ります。

1. 左メニュー「Storage」→「New Network Volume」。
2. データセンターは **H100 / A100 / L40S が選べる場所**を選ぶ（ボリュームはその場所のGPUでしか使えません）。
3. 容量は **150GB**（重み + 動画。10分動画を何本も作るなら増やす）。

### 手順 3：GPU の Pod を起動する

1. 「Pods」→「Deploy」。手順2のボリュームを選択。
2. GPU は **H100**（なければ A100 80GB）。
3. テンプレートは **「RunPod PyTorch」**（Ubuntu + CUDA 12.x のもの）。
4. 「Edit Template」で **HTTP ポートに `8501` を追加**（ブラウザ画面用）。
5. 「Deploy On-Demand」。起動したら「Connect」→「Web Terminal」（または SSH）を開く。

### 手順 4：このプログラムを取得する

Web Terminal で：

```bash
cd /workspace
```

```bash
git clone https://github.com/ty-45-ai/proactively.git
```

（非公開リポジトリの場合は GitHub のトークンが必要です。わからなければ `longvideo` フォルダを zip でアップロードしても動きます。）

### 手順 5：セットアップ（1回だけ・20〜40分）

```bash
bash /workspace/proactively/longvideo/scripts/setup_runpod.sh
```

やっていること：GPU の確認 → ffmpeg → LongCat-Video の取得（動作確認済みコミットに固定）→ Python 環境（PyTorch 2.6 + CUDA 12.4 + flash-attn）→ モデルの重みのダウンロード。
すべて `/workspace` に入るので、Pod を止めて再開しても入れ直し不要です。途中で切れたら同じコマンドをもう一度実行すれば続きから進みます。

### 手順 6：画像1枚 → 動画（コマンドで動作確認）

```bash
bash /workspace/proactively/longvideo/scripts/smoke_test.sh
```

付属のサンプル画像から約6秒の動画を作ります。自分の画像なら：

```bash
bash /workspace/proactively/longvideo/scripts/smoke_test.sh /workspace/my.png "She slowly turns her head toward the camera and smiles. Realistic, stable camera."
```

最後に `完成: /workspace/jobs/<ID>/output.mp4` と表示されれば成功です。表示された時間と VRAM を控えておいてください（GPU 比較の材料）。

### 手順 7：ブラウザ画面を起動する

```bash
LVGEN_PASSWORD=好きなパスワード LVGEN_GPU_PRICE=3.49 bash /workspace/proactively/longvideo/scripts/start.sh
```

RunPod の「Connect」→「HTTP Service [Port 8501]」を開く（`https://<POD_ID>-8501.proxy.runpod.net`）。
パスワードを入れると操作画面が出ます。

### 手順 8：終わったら Pod を停止

「Pods」→「Stop」。**停止中は GPU 料金はかかりません**（ボリュームの保管料のみ）。
次回は Pod を起動 → 手順 7 だけで再開できます。

## 4. 画面の使い方

1. 「＋ 新規作成」で画像をアップロード。
2. 長さ（6秒〜20分）、生成モード（高速 / 高品質）、720p/30fps 高画質化、出力解像度・FPS を選ぶ。
3. 動きの指示（プロンプト）を英語で書く。**1行 = 1セグメント（約5秒）**。1行だけなら全部同じ指示。
4. 「生成開始」。ブラウザを閉じても生成は続きます。
5. セグメントが1つできるたびにプレビューが表示されます。気に入らないセグメントは「作り直す」で、
   プロンプトを変えて**そこから後ろだけ**作り直せます（後ろは前の続きとして作られるため）。
6. 完成したら「完成動画をダウンロード」。

途中で止まったり失敗したりしても、「続きから再開」で完成済みの部分はそのまま使われます。

## 5. フォルダ構成

```
longvideo/
├ app.py                 ブラウザ画面（Streamlit）
├ lvgen/
│ ├ backends.py          LongCat-Video の呼び出し（1GPU, torchrun 不要）／テスト用モック
│ ├ runner.py            セグメントを順に生成 → 高画質化 → 連結（途中再開対応）
│ ├ jobs.py              ジョブ・セグメントの保存と状態管理
│ ├ worker.py            常駐ワーカー（モデルを1回だけ読み込む）
│ ├ videoio.py           FFmpeg での読み書き・連結・書き出し
│ └ cli.py               コマンドで1本作る
├ scripts/               RunPod 用: setup_runpod.sh / download_weights.sh / smoke_test.sh / start.sh
└ tests/                 GPUなしで動くテスト（モック使用）
```

### 生成の中身（公式デモと同じ設定）

| 処理 | 設定 |
|---|---|
| 1本目 | `generate_i2v`（480p, 93フレーム） |
| 2本目以降 | `generate_vc`（前の末尾13フレームを条件に 93 フレーム、うち新規 80） |
| 高速モード | 蒸留 LoRA（`cfg_step_lora`）, 16 ステップ, CFG 1.0 |
| 高品質モード | 50 ステップ, CFG 4.0, ネガティブプロンプトあり |
| 高画質化 | `refinement_lora` + Block Sparse Attention で 720p/30fps。前セグメントの高画質版の末尾26フレームを条件にしてつなぎ目をそろえる |
| 劣化対策 | 次の条件に使うフレームは可逆圧縮（libx264rgb crf 0）で保存し、圧縮劣化が113回積み重ならないようにした |

## 6. GPUなしでの動作確認（開発用）

```bash
cd longvideo && pip install -r requirements-ui.txt && python -m pytest -q tests
```

```bash
LVGEN_BACKEND=mock LVGEN_JOBS=./jobs LVGEN_PASSWORD=test python -m lvgen.worker &
LVGEN_JOBS=./jobs LVGEN_PASSWORD=test streamlit run app.py
```

モックは画像をゆっくりズームするだけのダミーです。画面・再開・作り直し・連結の確認に使います。

## 7. 困ったとき

| 症状 | 対処 |
|---|---|
| `この GPU は第1段階では未対応` | RTX 5090 / B200 では動きません。H100 / A100 / L40S で Pod を作り直す |
| `CUDA out of memory` | `LVGEN_OFFLOAD_TEXT_ENCODER=1 LVGEN_OFFLOAD_KV_CACHE=1` を付けて start.sh。それでも駄目なら 80GB の GPU へ |
| flash-attn のインストールが30分以上終わらない | ビルド済みファイルが合わずソースからビルドしています。待つか、Python 3.10 / 3.11 のテンプレートで Pod を作り直す |
| 画面に「ワーカー未起動」 | `tail -f /workspace/logs/worker.log` でエラーを確認し、start.sh を再実行 |
| 重みのダウンロードが途中で止まる | `bash scripts/download_weights.sh` を再実行（続きから） |

## 8. 次の段階でやること

- **第2段階**：10分以上でも人物・衣装がぶれないように、定期的に元画像を参照し直す仕組み（例：数セグメントごとに元画像を条件に戻す）と、ぶれの自動検出（顔の類似度など）を追加。
- **第3段階**：画像から自動でシーン構成・プロンプトを作る機能（ローカルの画像理解モデルを使い、有料APIは使わない）。
- **第4段階**：1分 → 3分 → 10分 → 20分 と伸ばしながら一貫性を検証。2枚以上のGPUでの並列化（公式の context parallel）も検討。
- **第5段階**：1080p への AI アップスケール（Real-ESRGAN 等）、フレーム補間、音声付け、料金の最適化。

## 9. 利用上の注意

このシステム自体には内容のフィルタがありません。素材は「成人の架空キャラクター」または「明確な同意を得た成人」に限るという方針を守り、
実在の人物を本人の同意なく使わないでください。モデルや依存ライブラリのライセンスは更新されることがあるので、導入時に最新版を確認してください。
